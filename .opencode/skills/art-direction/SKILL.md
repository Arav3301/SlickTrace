# SlickTrace Art Direction Skill

## Purpose

Use this skill whenever designing, reviewing, or modifying SlickTrace UI.

The goal is to maintain a premium, readable, map-centric maritime investigation product that does not look AI-generated.

## Core Direction

SlickTrace should feel like:

- a premium editorial geospatial product
- a marine investigation workspace
- a modern cartographic tool
- a serious evidence-analysis interface
- clear enough for a non-technical judge to understand quickly

It should NOT feel like:

- an AI SaaS dashboard
- a cybersecurity command center
- a dark military HUD
- a generic admin panel
- a bento-grid startup website
- a scientific interface with microscopic text

## Non-Negotiable Readability

Premium does not mean small typography.

Never make text tiny just to make the interface look sophisticated.

The product may be presented on a laptop or projector.

Therefore:

- candidate names must be easy to read
- important values must be visually prominent
- map labels must be readable without squinting
- metadata can be smaller, but never microscopic
- body text must feel comfortable
- evidence should be understandable from normal viewing distance

If information is hard to read, increase size before adding visual decoration.

## Color

Do not flood the interface with blue.

Preferred balance:

- warm off-white / stone background
- dark ink / deep navy typography
- muted marine blue as a secondary color
- signal orange / amber for selected evidence
- restrained green for strong states
- neutral gray for dividers and secondary information

Avoid:

- cyan everywhere
- purple
- blue gradients
- neon
- glowing map elements
- blue-on-blue dashboards

Color must communicate meaning, not just technical aesthetics.

## Typography

Typography should create hierarchy.

Use:

- confident page titles
- strong candidate names
- clear labels
- tabular numerals for data
- generous line height
- restrained monospace only for coordinates, IDs, timestamps, or technical values

Avoid:

- tiny uppercase everywhere
- excessive letter spacing
- overly thin font weights
- faint gray text
- excessive monospace styling

## Layout

The map is the main visual element.

Do not wrap the map in a small card.

Prefer:

large map canvas
+
evidence rail
+
investigation header
+
optional timeline / detail panel

Avoid:

sidebar
+
four KPI cards
+
eight rounded cards
+
small map card

## Containers

Reduce unnecessary containers.

Prefer:

- whitespace
- rules
- alignment
- grouping
- typography

Use containers only when they solve a real hierarchy or interaction problem.

Avoid:

- rounded rectangle around every data point
- border around every section
- 24px border radius
- excessive card stacks

Preferred radius:
4px to 8px.

Some elements may use zero radius.

## Map Design

Map should be visually calm.

Selected vessel:
strong emphasis

Other top candidates:
muted

Background tracks:
very faint

Detected slick:
clear but not fluorescent

Avoid:

- rainbow vessel tracks
- neon polygons
- fake radar rings
- fake scan animations
- tiny map labels
- overly technical map controls

## UI Review Test

Before accepting a screen, ask:

1. Does this look like a generic AI-generated dashboard?
2. Is blue being overused?
3. Is any text unnecessarily small?
4. Can a judge understand the main information in 5–10 seconds?
5. Is the map visually dominant?
6. Are there unnecessary cards?
7. Could the same UI belong to a finance or analytics product?

If the answer reveals generic design, redesign before continuing.

## Design Priority

Always prioritize:

1. clarity
2. hierarchy
3. readability
4. spatial understanding
5. evidence comprehension
6. polish

Decoration comes last.
