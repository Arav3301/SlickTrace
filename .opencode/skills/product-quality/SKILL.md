# SlickTrace Product Quality Skill

## Purpose

Use this skill before considering any feature or screen complete.

## Product Standard

SlickTrace should feel like a finished prototype, not a collection of components.

Every visible interaction should work.

No dead UI.

No fake actions.

No placeholder values when real demo data exists.

## Data Integrity

Use the real data from the SlickTrace demo bundle.

Never invent:

- vessel names
- MMSIs
- candidate rankings
- association scores
- model metrics
- slick areas
- timestamps
- coordinates

If data is unavailable, show an honest empty or unavailable state.

## Demo Truthfulness

The website initially replays precomputed outputs.

Never label this as live inference.

Use:

VALIDATED REPLAY

or equivalent wording.

Explain that the results were generated by the real SlickTrace ML + AIS pipeline and are replayed for demo reliability.

## Required Quality Checks

Before finishing any major feature:

- run TypeScript check
- run lint
- run build
- check console errors
- check overflow
- check responsive layout
- check keyboard interaction
- check selected states
- check loading states
- check empty states
- check error states

## UI Quality

Avoid:

- generic component-library defaults
- obvious template UI
- unused icons
- inconsistent spacing
- random border radius
- arbitrary colors
- excessively small text
- giant empty sections

## Interaction Quality

Buttons must do something.

Candidate selection must update map/evidence.

Layer controls must work.

Tabs must work.

Navigation must work.

No decorative controls that pretend to be functional.

## Code Quality

Use:

- TypeScript strict mode
- reusable domain-specific components
- meaningful naming
- centralized data models
- clean loading / parsing logic
- accessible interactive elements

Avoid:

- giant single-page components
- duplicated constants
- hardcoded presentation values scattered across files
- magic numbers without explanation

## Build Philosophy

Do not build every feature at once.

Work in vertical slices.

Example:

1. load investigation data
2. render map
3. render candidate list
4. connect selection
5. add evidence breakdown
6. polish

Validate each step before continuing.

## Final Question

Before marking work complete, ask:

"Would this survive a live SIH judge demo without explanation or excuses?"

If not, fix it.
